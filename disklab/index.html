The Core Problem

The requests don't arrive in a convenient order.

Processes running on your computer issue read and write requests to storage asynchronously. When files are fragmented across non-adjacent cylinders, naive scheduling forces the mechanical head to swing wildly across the platter.

Dominant Mechanical Delay (~3–10 ms)

1. Seek Time

Radial traversal of the actuator arm across concentric tracks. The read/write head must physically accelerate, traverse cylinders, decelerate, and settle on the target track. This physical travel dominates overall I/O latency.

Rotational Wait (~2–4 ms)

2. Rotational Latency

Waiting for the spinning platter to rotate the target sector beneath the sensor head (~4.17 ms average at 7,200 RPM; ~3.0 ms at 10,000 RPM).

Electronic Reading (<0.1 ms)

3. Transfer Time

High-speed electromagnetic reading and transmission of bits into drive buffer cache as sectors sweep past the head sensor.

Disk Cylinders

Concentric circular tracks numbered from 0 (innermost) to diskSize - 1 (outermost). Moving between tracks requires physical radial movement of the read/write head assembly.

Initial Head Position

The cylinder where the disk actuator arm currently rests when scheduling decisions begin. Every pending request's seek distance is measured relative to the active head position.

Request Queue

An ordered FIFO buffer of pending block requests waiting for disk I/O. Arriving from different processes, the queue positions rarely align with sequential disk cylinders.

Disk-Head Movement

The traversal distance in cylinders: \(|\text{target} - \text{current}|\). Because mechanical seek time dominates I/O delay, minimizing cumulative head travel directly improves total disk throughput.

Scheduling Algorithm

The operating system policy governing the service sequence of pending requests. The algorithm balances fairness, implementation complexity, and mechanical seek minimization.

Logical Model vs. Physical Architecture

CD Platter Metaphor: The central circular platter is an intuitive visual metaphor. In real computer hardware, Hard Disk Drives (HDDs) employ multiple double-sided magnetic platters spinning on a shared spindle, while Compact Discs (CDs) are single-track spiral optical media read by semiconductor lasers.

Logical Cylinder Mapping: In operating system theory and this simulator, cylinder indices represent a 1D logical address space mapped to concentric tracks. Real enterprise disks also account for rotational latency, sector layout, and internal drive-controller remapping.

The Scheduling Policies

Two philosophies. Radically different paths.

Compare the foundational First Come, First Served approach against the proximity-driven Shortest Seek Time First heuristic.

FIFO Principle

First in. First served.

First Come, First Served (FCFS) processes incoming disk requests in the exact order they arrive in the I/O queue.

Core Virtue Strict Fairness

Every request is guaranteed to be serviced in arrival order. Starvation is impossible because no request is ever postponed in favor of a closer neighbor.

The Mechanical Cost Severe Arm Thrashing

If requests alternate between inner and outer tracks, the disk head repeatedly traverses the entire platter radius, wasting time and increasing mechanical wear.

Order of Execution:
53 (Start) → 98 → 183 → 37 → ...
Proximity Principle

The nearest request gets served next.

Shortest Seek Time First (SSTF) repeatedly chooses the pending request with the minimum absolute distance from the current head position.

Core Virtue Seek Minimization

By greedily servicing proximate cylinders first, SSTF drastically cuts total mechanical seek distance and boosts overall I/O throughput.

The Inherent Risk Starvation Vulnerability

Requests located on distant tracks may wait indefinitely if a steady stream of new requests keeps arriving near the current head position.

algorithm FCFS(initialHead, queue):
    currentHead ← initialHead
    totalMovement ← 0
    sequence ← [initialHead]
    
    for each request in queue:
        distance ← |request - currentHead|
        totalMovement ← totalMovement + distance
        sequence.append(request)
        currentHead ← request
        
    averageMovement ← totalMovement / length(queue)
    return sequence, totalMovement, averageMovement

Step-by-Step Breakdown

  1. Preserve Arrival Sequence: The queue is evaluated in the exact order submitted by callers without sorting or reordering.
  2. Consecutive Distances: At each step \(i\), calculate absolute difference \(|c_i - c_{i-1}|\).
  3. Accumulate Seek: Sum up all individual movements to obtain total cylinder displacement.
  4. Module Mapping: Implemented inside algorithms.js → runFCFS(). Zero mutation of the original array.
algorithm SSTF(initialHead, queue):
    currentHead ← initialHead
    pending ← copy(queue)
    totalMovement ← 0
    sequence ← [initialHead]
    
    while pending is not empty:
        bestIndex ← 0
        minDist ← |pending[0] - currentHead|
        
        for i from 1 to length(pending) - 1:
            dist ← |pending[i] - currentHead|
            if dist < minDist:
                minDist ← dist
                bestIndex ← i
            else if dist == minDist:
                // Deterministic tie-breaker: earlier queue index wins
                if pending[i].originalIndex < pending[bestIndex].originalIndex:
                    bestIndex ← i
                    
        chosen ← pending.remove(bestIndex)
        totalMovement ← totalMovement + minDist
        sequence.append(chosen)
        currentHead ← chosen
        
    return sequence, totalMovement

Step-by-Step Breakdown

  1. Greedy Candidate Evaluation: On every iteration, inspect all remaining pending requests to find the one minimizing seek distance.
  2. Deterministic Tie-Breaking: When two requests lie equidistant in opposite directions (e.g. at distances \(+10\) and \(-10\)), DiskLab deterministically chooses whichever request appeared earlier in the input queue.
  3. Remove from Pending: The serviced request is removed from the pending pool, and the head advances to its position.
  4. Module Mapping: Implemented inside algorithms.js → runSSTF().

Why Modular Architecture Matters

In production software engineering and computer science pedagogy, decoupling responsibilities creates maintainable, testable software:

Separation of Concerns

Input validation (validation.js) has zero coupling to SVG rendering (visualization.js). Business logic remains purely algorithmic.

Unit Testability

Pure functions in algorithms.js and metrics.js can be tested headlessly via automated CLI suites (such as tests/test_runner.js) without browser DOM dependencies.

Extensibility

Adding new disk scheduling algorithms (such as SCAN, C-SCAN, or LOOK) requires only a new function in algorithms.js and zero refactoring of visualization or validation pipelines.

Scheduling is a decision about movement.

FCFS values arrival order. SSTF prioritizes proximity. Understanding the trade-off is the first step toward understanding storage performance.
